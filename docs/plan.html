01 · The short version

Key decisions

Recommended

One small Docker container, connected to Dolibarr

A single Python app using SQLite and an in-process job queue: no Postgres, no Redis, no Postiz. It idles around 300 MB. Dolibarr remains the source of truth for contacts, unsubscribes and the email record.

Recommended

Claude Pro connects through MCP

The Studio runs an MCP server. You open Claude Code (or claude.ai) with the Pro plan, run one command, and Claude works through the queue of uploads that need captions and planning, then submits drafts. No API key is used.

Recommended

The Studio tells you when Claude is needed

It tracks the work only Claude can do and emails you when a session is due. The email lists what's waiting, roughly how long it will take, and the exact command to run.

Recommended

Built-in publishers, phased by how easy each API is

The Studio talks directly to each platform's free API. Channels whose APIs are gated or paid use "assisted posting" instead: a one-tap ready-to-post pack on your phone. That keeps the RAM use small.

Recommended

Email is announcement-only, enforced in code

Social posts can't be added to an email at all. Email uses a separate Announcement type for classes, events and important org news, with a frequency cap.

Recommended

Google Calendar drives event content

The Studio reads your class and event calendar. Each new event automatically queues a promo set and an email announcement draft for Claude to write and you to approve.

Dropped

Postiz, Metricool API, Claude API, GitHub as the content bridge

Postiz needs several extra database and workflow containers. The Metricool API and Claude API cost money. GitHub is a poor fit for media and approvals, so it holds only the code and the Claude commands. Details are in the sections below.

02 · Non-negotiable

Approval rules

Rule 1, enforced in the database

Nothing leaves the Studio until a signed-in person with the Approver role has approved that exact version.

That covers every channel: social posts, the ready-to-post pack, the website feed, Google Business Profile, ad copy and email. Claude and the MCP connection can create and edit drafts. They can never approve.

Rule 2, enforced in the data model

Email blasts contain only Announcements: classes, events and important organizational news. Social posts can never be sent as email.

Announcements are a separate record type with their own template. No feature, button or MCP tool can turn a social post into an email. The details are in the Email section.

How Rule 1 is enforced

  • Only a person can approve. Every post moves through a state machine, and only the Approve button in the web UI, clicked by an Approver, moves it to approved.
  • Approval covers one exact version. The approval stores a hash of the caption, media files, channel settings and time slot. Any later edit sends the post back to review.
  • Every publisher checks again before it sends. A failed check blocks the send and is logged.
  • Approvers see the final output for each channel. That means the rendered video with music, each platform's crop, the full caption for each platform and the scheduled time.
  • Email gets extra checks. The approval screen shows the recipient count and the list filter and sends a test copy to the approver. A second approver is optional.
  • Every change is logged. Who generated, edited, approved, rejected and published each post, and when.

03 · Using the Pro plan

Claude connection

Without an API key, Claude only works when someone opens a chat. The Studio handles everything that doesn't need AI on its own. It saves up the work that does need Claude and asks for a session at the right time.

How the connection could work

OptionHow it worksVerdict
MCP server

The Studio exposes tools at /mcp. Claude Code, Claude Desktop or claude.ai connect to it and call those tools directly. Tool results include media previews, so Claude can see the photos and video frames.

Use this Live data, no copying, and the Studio controls exactly what Claude can do.

GitHub

The Studio commits a "work packet" to a repo, Claude edits files and commits drafts back, and the Studio imports them.

Not for content Media doesn't belong in git, it's slow, and it creates two copies of every draft. GitHub holds the code and the Claude commands only.

Export / import

Download a work packet zip, attach it to a chat, paste the JSON reply back.

Fallback Works with no setup and from anywhere. Clunky, but it's a backup if MCP is down.

Two ways to connect

Phase 1

Claude Code on a staff computer

Connect once with a personal Studio token. The server can stay on your LAN or VPN, with nothing exposed to the internet. The repo includes ready-made slash commands, so a session is one command.

Phase 3

claude.ai or the Claude mobile app

Pro supports custom remote MCP connectors. The /mcp path has to be reachable from the internet, and the Studio adds an OAuth login. This lets you run a session from your phone after hack night.

# one-time, on the computer you run Claude Code from
claude mcp add --transport http cgw-studio https://studio.cgw.lan/mcp \
  --header "Authorization: Bearer <your-studio-token>"

# then, whenever the Studio emails you
claude "/cgw-session"

Staying within Pro usage limits

  • Work arrives small. The Studio does the heavy lifting first: it shrinks images, picks key frames and transcribes audio before Claude sees anything. Claude never receives full-size video.
  • Sessions are short. The queue is split into sessions of about 10 items, around 15 minutes each. Two sessions a week covers 3 posts a week plus events.
  • Nothing breaks if a session is skipped. Items just wait, and the reminder escalates as a deadline gets closer. A person can always write a caption by hand in the web UI instead.

One post, many versions

  • Each post has one "story" (media plus message) and a version for each channel. The Studio only offers channels that accept the media: a video post won't offer a Google Business Profile video, and a text-only update won't offer Instagram.
  • Claude writes each version to the platform's limits and customs: "link in bio" on Instagram, the full link on Facebook, 300 characters on Bluesky, a short title and #Shorts on YouTube, keywords on Google Business Profile.
  • The approver sees every version side by side and can untick any channel before approving.

The ready-to-post pack

For assisted channels, the Studio sends a push notification (through a free self-hosted ntfy server, or by email) at the scheduled time. The link opens a phone page with the final media, a "Save to phone" button, a copy button for the caption, and a button that opens the app. After posting, tap "Mark posted" and paste the post's URL so its metrics can be tracked.

07 · Getting media in

Media workflow

  1. Drop it inUpload several files at once from your phone or desktop, or drop them in a shared Unraid folder. Add one line, for example "Sam's walnut ukulele, first laser-engraved rosette."
  2. Consent checkTag the people shown. The Studio checks the photo-release field on each person's Dolibarr contact. Anyone without a release, and any minor, blocks approval until that's resolved.
  3. Prepared automatically, no AITranscode, thumbnails, key frames, transcript and platform crops. The item goes into the "needs Claude" queue.
  4. Claude sessionAt the next /cgw-session, Claude looks at the media and writes the description, alt text, pillar, 3 caption styles and a version for each channel, and requests the video cut it wants.
  5. You editSwap music, trim, adjust subtitles, rewrite captions, untick channels, change the time slot.
  6. ApproveThe Approver reviews every channel version of the final render.
  7. Out the doorDirect channels publish at their slot. Assisted channels send the pack to your phone at their slot.

The media library is searchable by person, tool, project, event or description. It shows where each file has already been used and keeps an "unused gems" list that the planner draws from first.

Caption voice guide (an MCP resource)

  • Write like a member talking to a friend about the shop: specific, warm and dry rather than hyped.
  • Name the real thing, such as "1/4" baltic birch on the laser," not "an amazing creation."
  • Use at most one emoji, and only when it adds meaning. Banned: "game-changer," "unleash," "level up," and rocket emojis.
  • Follow Hook → Value → CTA from the old spreadsheet, with 3–5 targeted hashtags. Always write three styles (straight, warm, playful) so a person picks the tone.

10 · Classes & events

Google Calendar

  • Reading the calendar. The Studio checks the calendar's private iCal address every 15 minutes. No Google login or OAuth is needed, and it's read-only. You can switch to the Calendar API later if you want write-back.
  • A light convention for event descriptions. Optional lines like Signup: https://…, Price: $25, Promote: no and Email: yes. Claude reads the rest of the description as normal text.
  • New event: the Studio creates a promo set (announce at −14 days, reminder at −2, day-of story, recap prompt at +1) and, if the event is email-eligible, an Announcement draft. All of these wait in the "needs Claude" queue.
  • Changed event: if a date, time or price changes, any approved post about it goes back to review and the approver is told why.
  • Cancelled event: scheduled posts about it are pulled and the approver is notified. A cancellation announcement is drafted if the event had already been announced by email.
  • Website: the site can embed the Google Calendar directly. The Studio's feed covers news and projects.
11 · Announcements only

Email announcements

What can be emailed

Only classes, events and important organizational news. That rules out member-project posts, memes and general social content.

A Membership or Awareness social post can't be added to an email. Shop humor is tagged "social only."

  • A separate record type. An Announcement is created from a calendar event or with "New important announcement" (editors and admins only). It has its own professional template: logo, heading, date and location block, sign-up button and footer.
  • Frequency cap. By default at most 1 email per week and 4 per month. Several events in the same week are combined into a single "Coming up at CGW" digest. Going over the cap needs an admin override, which is logged.
  • Audience. Recipients are Dolibarr contacts in an "Email announcements" category, about 50 people today. Anyone with no_email set or on the suppression list is always excluded.
  • Approval. The approver sees the rendered email, the recipient count and a test send. A second approver is optional.
  • Sending. Through the SMTP2GO API, with a List-Unsubscribe header and one-click unsubscribe (RFC 8058).
  • Record. Each send is logged on the contact in Dolibarr as an agenda event, so the email history stays in Dolibarr.

Unsubscribes, with Dolibarr as the source of truth

  • The unsubscribe link goes to a Studio page that needs no login. It sets the contact's opt-out in Dolibarr through the REST API and adds the address to a local suppression list as a backup.
  • Dolibarr's own Emailing module sets the same opt-out flag, so unsubscribing from either system has the same effect. SMTP2GO bounce and complaint webhooks also write back to Dolibarr.
  • An alternative, since there are only 50 contacts: the Studio could create the mailing in Dolibarr's Emailing module and let Dolibarr send it through SMTP2GO. That keeps unsubscribe handling and logging entirely inside Dolibarr. Phase 4 starts by testing which approach works more cleanly on the latest Dolibarr version.

13 · What's working

Metrics

  • Every night the Studio pulls metrics from Meta (Instagram, Facebook, Threads), YouTube and Bluesky, and keeps the history permanently. Assisted posts are tracked by the URL entered at "Mark posted."
  • Every post is tagged by pillar, format, audience, hook and CTA, which makes "what works" a query.
  • UTM tags on every Givebutter and website link show which posts lead to memberships and donations. Hack-night attendance can be logged weekly.
  • Metricool free stays as an extra dashboard and for tracking other makerspaces.
  • /cgw-review reads all of this through get_metrics and writes the monthly analysis, which is saved so you can check whether its advice helped.
14 · Running it

Deploy & auth

  • One container, cgw-studio, with a 1 GB memory cap. Optionally add ntfy (about 20 MB) for phone push.
  • Volumes: /mnt/user/appdata/cgw-studio for the SQLite database and config, and /mnt/user/cgw-media for media. The nightly backup is a SQLite snapshot plus the media share.
  • It ships as a docker-compose file and an Unraid Community Apps template.

Login: two layers

  1. Reverse-proxy auth in front. The Studio trusts the Remote-User header only when it comes from the proxy's IP.
  2. Studio login with a local account and password, matched to the proxy user. Roles are assigned in the Studio: Contributor, Editor, Approver, Admin.

What has to be public

  • /m/<id>: approved media only. Instagram and Threads fetch media from a URL, so this path must be reachable from the internet.
  • /feed/*: the website feeds. /u/<token>: unsubscribe. /hooks/smtp2go: signature-verified webhooks.
  • /mcp: only if you use claude.ai or mobile (Phase 3), protected with OAuth. With Claude Code only, it can stay LAN-only.

Secrets live in an .env file on the server and never in the repo: Meta app secret, Bluesky app password, SMTP2GO key, Dolibarr API key, and the Google Calendar private iCal URL.

17 · Need your input

Open questions
