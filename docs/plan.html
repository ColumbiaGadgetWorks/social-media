01 · The short version

Key decisions

Recommended

A standalone Docker app, connected to Dolibarr

Not a Dolibarr plugin. Video editing, AI and background jobs need Python and ffmpeg, which a PHP module can't run well. Dolibarr stays in charge of contacts, unsubscribes and the email record.

Recommended

Postiz posts to social media, for free

Postiz is an open-source scheduler you run on the Unraid box. It posts to Instagram, Facebook, Threads, Bluesky, LinkedIn, YouTube, TikTok and more. The Studio sends approved posts to it through its API. There are no fees or post limits.

Recommended

Metrics from Meta, with Metricool free on the side

The Studio pulls post insights directly from Meta at no cost and keeps the full history. Metricool's free plan stays useful for its dashboard and competitor tracking, but it no longer does the scheduling.

Recommended

AI through your Claude subscription

The creative work happens in Claude Code chats, through the Studio's MCP connection. That uses the Claude plan you already have instead of a separate API bill. A paid API key is optional and the Studio works without one.

Recommended

An RSS feed for the website

Approved posts marked "website" go into a public feed and an events calendar file, so you write each update once.

Not recommended

RSS as the bridge to social media

RSS-to-social tools can't schedule a time slot, handle video poorly, and the free ones (IFTTT, dlvr.it) cap posts or add their branding. A direct API push to Postiz is free and keeps the approval check in one place.

Dropped

Metricool API

It's only on the paid Advanced plan, about €43 a month. Metricool's free plan also caps scheduling at roughly 20–50 posts a month, too few for 3 posts a week across platforms plus stories.

03 · Non-negotiable

The approval rule

Hard rule, enforced in the database

Nothing leaves the Studio until a signed-in person with the Approver role has approved that exact version.

"Leaves" covers Postiz, the manual "ready to post" pack, email sends, the RSS feed and the website. AI, API tokens and the Claude Code connection can create and edit drafts. None of them can approve.

How it's enforced

  • Every post moves through a state machine. Only the Approve button in the web UI, clicked by a user with the Approver role, can move a post into approved.
  • Approval covers one exact version. The approval stores a hash of the caption, media files and platform settings. Any later edit, even fixing a typo, sends the post back to review.
  • Every exporter checks before it sends. The Postiz push, the "ready to post" pack, the email sender and the RSS feed each check the approval record and hash. A failed check blocks the send and is logged.
  • The approval screen shows the final output. Approvers see the rendered video with music, the cropped images for each platform, the full caption with hashtags and the scheduled time. They never approve a summary.
  • Email blasts need extra checks. Email can't be unsent, so a blast also shows the recipient count and the list filter and sends a test copy. You can optionally require a second approver.
  • Every change is logged. Who generated, edited, approved, rejected and exported each post, and when.

05 · Getting media in

Media workflow

This needs to be quick enough that a member will do it from their phone at the end of hack night.

  1. Drop it inUpload several files at once from your phone or desktop, or have the Studio watch a shared Unraid folder. Add one line, for example "Sam's walnut ukulele, first laser-engraved rosette," and pick a project or event if you like.
  2. Consent checkTag the people shown. The Studio checks their photo release, stored on their Dolibarr contact. Anyone without a release, and any minor, is flagged, and the post can't be approved until that's resolved or they're blurred or cropped out.
  3. The Studio analyzes itIt transcodes, pulls key frames and transcribes any speech. The next time Claude runs, in your chat or the weekly routine, it describes what's shown (tools, materials, techniques) and suggests a content pillar and post types. With the optional API key, this happens right after upload.
  4. Variants are generatedPlatform crops (9:16 reel, 4:5 feed, 1:1), a short cut with subtitles, three caption styles and a hashtag set. Each comes with a short explanation of why it was suggested.
  5. You editSwap music, trim clips, adjust the subtitles, rewrite captions by hand or with "make it shorter / warmer / less salesy," and change the schedule slot.
  6. Submit and approveThe Approver sees the final render. Approve, request changes with a comment, or reject.
  7. Out the doorThe post goes to Postiz for its time slot, to the RSS feed if marked for the website, and to the next newsletter digest if marked for email.

The media library

  • Search everything by person, tool, project, event or AI description, for example "all CNC router clips from 2026."
  • Each file shows where it has been used, so the same photo isn't posted twice in a month.
  • An "unused gems" view lists strong media that hasn't been posted yet. The idea engine draws from it.
06 · Polished, not cringe

Editing style

The AI edits within a brand kit you define once. It doesn't invent a new style for each post.

ToolWhat it doesGuardrail
Brand kit

Logo bug, 2 fonts, 4 colors, lower-third style, end card with membership/hack-night CTA

Every template uses only the kit. No random fonts.

Subtitles

Burned-in captions from Whisper, styled for readability, word-level timing

No bouncing emoji captions. One clean style, editable text.

Smart cuts

Picks the best 6–30 s from long clips (motion, faces, the "reveal" moment), cuts on beat

Always shows the source in/out points so a human can adjust.

Music

Picks from a local, licensed track library tagged by mood and tempo, ducked under speech

Only tracks with a recorded license. For Instagram trending audio, the post is marked "add trending sound in app."

Before / after

Split-screen or wipe templates for repairs and restorations

Works with two photos or a timelapse.

Meme mode

Shop-humor captions on member photos, using a few classic formats rendered in the brand fonts

Off by default per post. Never targets a person. Flagged for a second look in review.

Event graphics

Class and event cards built from the event record: title, date, price, sign-up link, QR code

Facts come from the record. The AI isn't allowed to change dates or prices.

Caption voice guide (included in every prompt)

  • Write like a member talking to a friend about the shop: specific, warm and dry rather than hyped.
  • Name the real thing, such as "1/4" baltic birch on the Epilog," not "an amazing creation."
  • Use at most one emoji, and only when it adds meaning. Avoid "game-changer," "unleash," "level up" and rocket emojis.
  • Follow the Hook → Value → CTA structure from your old spreadsheet. Facebook gets the full Givebutter link, Instagram says "link in bio," and both use 3–5 targeted hashtags.
  • Always generate three styles, straight, warm and playful, so the human picks the tone.

Scheduled routines

A Claude Code routine can run the same tools on a schedule, with no one in the chat. Two to start with: Monday, fill the next two weeks' gaps with drafts; 1st of the month, write the performance review and three campaign ideas. Either way, the results land in the review queue as drafts.

For routines that run in the cloud, the /mcp path needs to be reachable from the internet. It skips proxy auth and checks the per-user token instead, the same way the feeds do.

The repo also gets a CLAUDE.md describing the brand voice, pillars and approval rule, so Claude Code sessions working on the codebase follow the same rules.

09 · Getting posts out

Publishing & metrics

Postiz does the posting

  • Postiz runs as another container in the same stack. You connect Instagram, Facebook and any other platforms in Postiz once. For Facebook and Instagram that means creating a free Meta developer app, a one-time setup of about an hour.
  • The Studio pushes each approved post to Postiz's API with its final media, a caption for each platform and its time slot. Postiz holds it and publishes on time.
  • Postiz is locked down. Only admins can sign in to it, and it sits behind the same proxy auth. Nobody writes posts there, so it can't be used to skip approval. Its own approval features aren't needed.
  • Each platform gets its own version. Instagram says "link in bio" and Facebook gets the full Givebutter link, following the old spreadsheet's CTA rules. Bluesky and Threads get shorter captions.
  • A fallback is always there. If Postiz or a platform login breaks, the post card offers a "ready to post" pack to schedule by hand in Meta Business Suite, which is also free.

Metrics come from Meta, not Metricool

  • Every night the Studio pulls each post's reach, plays, saves, shares and link clicks from Meta's insights API. It uses the same free developer app and stores the history permanently.
  • Keep Metricool's free plan for its dashboard, best-time-to-post suggestions and competitor tracking of other makerspaces. Its free analytics only keep about 30 days of history, which is why the Studio stores its own copy.
  • Postiz also shows basic per-post analytics, which is handy for checking that a post went out.

Verify Before building on it, test Postiz with your Instagram account, specifically reels and carousels. Meta changes its rules often. If Postiz falls short, the Studio can post to Meta's API directly using the same developer app. That's more code to maintain but still free.

10 · Newsletters & announcements

Email blasts

Dolibarr owns who gets email and keeps the record. SMTP2GO handles delivery. The Studio handles writing, approval and sending.

  1. WritePick a template (monthly newsletter, class announcement, event, fundraising ask). Approved social posts can be added as newsletter blocks. Claude drafts the subject lines and body.
  2. Pick the audienceRecipients come from Dolibarr contacts, filtered by category or tag (members, class alumni, donors, newsletter list). Anyone with no_email set or on the suppression list is always excluded.
  3. ApproveThe approver sees the rendered email, the recipient count and a test send. A second approver is optional.
  4. SendEmails go through the SMTP2GO API in throttled batches that stay within your plan's daily and monthly limits. A blast that would go over the limit is split across days or blocked with a warning. Each one includes a List-Unsubscribe header and one-click unsubscribe (RFC 8058), which Gmail and Yahoo require for bulk senders.
  5. RecordEach send is logged to the contact in Dolibarr as an agenda event, so the email history stays in Dolibarr.

Unsubscribes, with Dolibarr as the source of truth

  • The unsubscribe link goes to a Studio page that needs no login. It sets the contact's opt-out in Dolibarr through the REST API and adds the address to a local suppression list as a fallback.
  • Dolibarr's built-in Emailing module already marks contacts no_email through its __UNSUBSCRIBE__ link. The Studio reads the same flag, so unsubscribing from either system has the same effect.
  • SMTP2GO webhooks for bounces, spam complaints and unsubscribes write back to Dolibarr and suppress the address.
  • Optional: a preferences page where people choose newsletter, classes and events, or fundraising, mapped to Dolibarr categories.
  • Verify Check that your Dolibarr version's REST API can write the contact opt-out field. If it can't, the small Dolibarr module listed in Key decisions adds an endpoint for it.
11 · The website

RSS & website feed

Yes, it's worth doing and it's inexpensive. Posts marked "website" at approval time appear in:

  • /feed/news.xml: RSS with images, for a "Latest from the shop" block on the website. WordPress, Squarespace and most builders can show an RSS feed.
  • /feed/events.ics: an events and classes calendar people can subscribe to, which the website can embed.
  • /feed/projects.json: a member project gallery feed, if the site wants a showcase page.

The feeds include only approved, website-flagged items, and media is served at web-friendly sizes. Use /feed/* as the only public, unauthenticated path besides the unsubscribe page and the public media used in posts.

13 · What's working

Metrics & analysis

  • Every post is tagged with pillar, format, audience block, hook, CTA, music, and whether people are shown. That makes "what works" a query instead of a guess.
  • Outcomes, not just likes. UTM tags on every Givebutter and website link show which posts drive membership sign-ups and donations. Hack-night attendance can be logged as a weekly number.
  • Metrics come from Meta's insights API every night and are kept permanently. Metricool free remains an extra view.
  • A dashboard showing reach and engagement rate by pillar and format, the best posting times, hook rankings, and email open and click rates by list.
  • Claude's monthly review, run as a Claude Code routine, is a written analysis with recommended changes. It's saved, so you can see whether last month's advice helped.
14 · Running it

Deploy & auth on Unraid

Containers (one docker-compose stack, plus an Unraid template)

  • studio-web: the FastAPI app and UI
  • studio-worker: ffmpeg, Whisper and AI jobs. Give it most of the CPU and an optional GPU.
  • postiz: the publisher, with its own Postgres, Redis and Temporal containers, as in its official compose file
  • postgres and redis for the Studio
  • Volumes: /mnt/user/appdata/cgw-studio for the database and config, and /mnt/user/cgw-media for originals and renders on the array
  • Nightly pg_dump to the array, included in your existing Unraid backup

Login: two layers, as you described

  1. Reverse-proxy auth (Authelia, Authentik or similar in front). The Studio trusts the Remote-User header only from the proxy's IP.
  2. Studio login with a local account and password (passkey optional). It's matched to the proxy user, and roles are assigned here.
RoleCan do
Contributor

Upload media, tag projects, write and edit drafts, submit for review

Editor

Everything above, plus manage the schedule, campaigns, brand kit and music library

Approver

Approve or reject posts and email blasts

Admin

Users, integrations, API tokens, settings

Public paths that bypass proxy auth: /feed/*, /u/<token> (unsubscribe), /m/<id> (approved media, which Meta needs to fetch), /mcp (per-user token), and SMTP2GO webhooks, which are verified by signature. Postiz also needs its Meta login callback URL reachable. MCP tokens are per-user, can be revoked, and can't approve anything.

Secrets are stored in environment variables or an .env file on the server and never in the repo: Postiz API key, Meta app secret, SMTP2GO key, Dolibarr API key, and the optional Claude API key.

17 · Need your input

Open questions

  1. Who pays for Claude today, and which plan? If it's a personal plan, the weekly routines would run on your account. Claude for Nonprofits (up to 75% off Team) could give the content team shared seats.
  2. How big is the email list? SMTP2GO's free tier is roughly 1,000 emails a month. A larger list needs a nonprofit discount request, a paid tier, or splitting sends across months.
  3. Where do classes and events live today? Dolibarr's Agenda or Events module, the website, Givebutter, or somewhere else? The Studio should read them from one place rather than have them typed in twice.
  4. Which Dolibarr version, and how are newsletter contacts organized? Categories, tags or a custom field. This also confirms whether the REST API can set the opt-out flag.
  5. Who approves? One person, or a small group? Should email blasts require two approvers?
  6. Do you keep photo releases today? On paper, a waiver form, or a Dolibarr field? Minors at classes are the main concern.
  7. Which platforms? Postiz makes extra platforms free. Bluesky, Threads, a YouTube Shorts channel, and LinkedIn for sponsors would cost only the setup time.
  8. What runs the website, and does CGW use Discord? The website determines how to show the feed. A members' Discord could be another way to submit media (see Other ideas).
  9. How much RAM, and a GPU, on the Unraid box? Postiz plus the Studio needs about 6–8 GB. A GPU is optional and speeds up subtitles and renders.
